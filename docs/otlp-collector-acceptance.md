# OTLP Collector interoperability and decoder regression

## Scope

The configured executable is tested with the official OpenTelemetry Collector
**0.161.0**, as both an independent source and an independent sink process. This
is separate from the application's Go packages and the independent Python HTTP
peers used by the existing [service contracts](../tests/otlp_service/run.py).
Use the [service guide](otlp-service.md) and [settings template](settings/otlp.yml)
for deployment configuration. This evidence does not declare production readiness.

The [read-only workflow](../.github/workflows/otlp-collector.yml) pins Go 1.27.1
and the official Linux amd64 Collector archive to SHA-256
`6c2af0731a53691e3771d82a4b71e2941a46de27af191e40c697b6ed8643e50e`.
The checksum was verified against both the release asset digest and its published
`.sha256` file. The workflow verifies it before executing the binary.

## Executable acceptance

[The harness](../tests/otlp_collector/run.py) uses this actual process topology:

```text
Independent caller -> source Collector -> recording proxy -> go-fluentd
  -> fault-injecting recording proxy -> sink Collector -> recorded JSON sink
```

Collector exporter queues and retries are disabled deliberately. The source
Collector's exporter uses JSON or protobuf and gzip. The application also exports
with gzip. The sink Collector decodes the payload and re-exports JSON for an
independent value comparison. Proxies preserve request and response outcomes;
the outage response is injected by the proxy, not generated by the Collector.

The matrix has **12 scenarios: logs/metrics/traces x JSON/protobuf x plain/gzip
WAL**. It does not cover every combination of transport compression. Each case:

1. Sends an otherwise valid large envelope through the source Collector and
   observes the application's **logical WAL admission limit** return HTTP 503.
   The source must not acknowledge it as accepted. This is not a physical-disk-full
   or failed-Sync test; those are different storage fault classes.
2. Accepts a small request while its downstream returns 503, records an actual
   failed export attempt, and SIGKILLs the application.
3. Restarts with the same generation and storage, restores downstream availability,
   and waits for the accepted destination outcome to be persisted; SIGKILLs again.
4. Restarts once more, sends a different request, requires new progress, and checks
   clean SIGTERM shutdown. Persisted successful outcomes must not be exported again.

Saved source receipts are checked against regenerated inputs. Fsynced proxy
ledgers require **exact uncompressed bytes across the application**, signal route,
content type, gzip, retry attempts and two successful exports. The terminal sink
checks exactly two items and the original Unicode values, integer metric boundary,
identifiers and nanosecond timestamps. Real Collectors decode/re-encode payloads;
unknown fields need not survive the Collectors. The byte-preservation assertion
starts at application ingress, not at the independent caller.

The lifecycle ledger records three process starts and exit statuses -9, -9, 0,
with matching process IDs and unchanged generation identity. After a successful
case, three independent saved-file mutations must fail their intended assertion:
changed exported bytes, a missing terminal item, or a falsely successful crash
exit. Each restoration must pass again. Parser errors or unrelated failures do
not count as detection. The complete campaign therefore checks **24 accepted
envelopes, 24 terminal items, 12 WAL refusals, 24 observed SIGKILL exits and 36
negative controls**. Retry attempt counts are measured, not assumed fixed.

The fixture is deliberately small: one log, one gauge point or one span per
request. This does not certify every OTLP field, metric type, backend, operating
system, load level, or Collector release. TLS/mTLS, authentication, partial and
permanent rejection contracts remain covered by the separate service/transport
suites; do not relabel those as new Collector-native rejection tests. Known
persisted outcomes do not imply exactly-once behavior in the remote-success /
local-receipt crash window.

## Reproduce and audit

Obtain the official `otelcol_0.161.0_linux_amd64.tar.gz` from the
[release](https://github.com/open-telemetry/opentelemetry-collector-releases/releases/tag/v0.161.0),
verify the checksum above and extract `otelcol`. From the repository root:

```sh
go mod verify
go build -mod=readonly -race -o /tmp/go-fluentd-collector .
GORACE='halt_on_error=1 exitcode=66' python3 tests/otlp_collector/run.py \
  --binary /tmp/go-fluentd-collector --collector /path/to/otelcol \
  --artifacts /tmp/otlp-collector-campaign
python3 tests/otlp_collector/run.py --audit-only \
  --artifacts /tmp/otlp-collector-campaign
```

Use a new artifact directory per campaign. Audit-only starts no service. Preserve
failed and interrupted campaigns too. Raw ledgers are synthetic test data, not
production telemetry. The Collector checksum/version and application hash are
recorded in the summary; hosted artifacts also retain source/dependency hashes.

## Additional decoder regression and integration boundary

The PR already contains the confirmed decoder correction: **msgp v1.1.9 and
fwd v1.1.2**, a raw-wire routing oracle, and its permanent GC-stress gate. This
increment preserves those commits and the exact dependency graph. See the
[root-cause guide](msgpack-gc-reliability.md); the production sender is unchanged.

The additional [literal-wire test](../library/fluentd_gc_test.go) isolates the
library decoder from both the sender and encoder. Eight workers decode a literal
packet while GC runs, checking the outer tag, map key, and value. The original
v1.1.2 dependency produced named assertion failures (`tag-3` became `ceTag`, and
a key was corrupted). A diagnostic copy changing only `UnsafeString` passed.
This independently confirms decoder corruption without attributing it to routing.

An early candidate tested upstream v1.1.4 before discovering that the PR had
advanced to the newer fix. That preliminary candidate and its passing tests are
retained as experiments, not final-head acceptance. **It was not published and
must not replace or downgrade the PR's v1.1.9 dependency.** Final acceptance must
use the reconciled source tree with the unchanged native module files, without
replacement modules or a custom modfile.

```sh
GOMAXPROCS=2 GOGC=10 go test -mod=readonly -race -count=20 \
  -run '^TestRegressionFluentDecodeStringLifetime$' ./library
GOMAXPROCS=2 GOGC=10 go test -mod=readonly -race -count=500 \
  -run '^TestRegressionFluentConcurrentTagRouting$' ./internal/senders
```

## Retained attempt boundaries

The first Collector invocation was interrupted before all cases finished. A later
protobuf trace audit caught an oracle mismatch: the existing protobuf fixture's
second span ID is `23` repeated eight times, whereas its JSON fixture uses `33`.
The auditor now expects the actual caller encoding; neither production code nor
the original fixtures were modified. An intermediate lifecycle-ledger edit also
failed before starting a case due to a port-unpacking error and was corrected.
Only complete campaigns using the final harness count as acceptance.

The first hosted preparation run rejected packages with `[no test files]` as
skipped tests. Its classifier was corrected while still rejecting all failures,
actual skipped tests, unexpected package skips, and wrong run/pass counts; injected
failure/skip records validate that distinction. Another run passed all native
and Collector checks but GitHub denied its final tree-object write. Neither run
updated the PR. Test success and publication success are tracked separately.

Receipts still have no compaction/TTL or aggregate disk quota. The logical WAL
threshold excludes receipt/preallocation costs and is not a filesystem quota.
Scheduler/throttle state is process-local. This increment adds no throughput,
power-loss, exactly-once, OTLP/gRPC, profiles, aggregation, sampling or temporality
conversion claim. Keep the generation, WAL and receipts together during recovery.
